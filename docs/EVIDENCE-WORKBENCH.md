# 证据核验工作台（PC 开发版）

## 本轮能力

侧栏「证据核验」不再只是顺序卡片，新增：

- 全课程状态统计：待核验、有争议、已通过、未通过；统计不随列表筛选变化，包含全部历史提交版本，不代表独立作品数量。
- 按来源名称、论断、作品标题、作者搜索；核验状态、作业与「全部 / 我可核验 / 我已核验 / 我的证据」筛选；每页20条服务端分页。争议优先，然后待核验，再已处理记录。
- 对照原始来源链接、来源摘录、需支持的论断、提交时的引用段落。链接只作为阅读跳转，不代表来源已经核实，不进行外网抓取。
- 核验历史展示操作者、结论、依据、时间及当时身份；教师裁定只追加记录，不删旧结论。
- 从教师评审来源区进入对应证据；有全文权限时可返回指定提交并定位引用段落。争议通知直接打开对应证据，不受当前分页或筛选影响。
- 空结果、冻结、作者自核、本人重复核验、教师已裁定均有明确说明；原生dialog支持键盘关闭、未提交依据离开确认与浏览器关闭警告。

## 权限与可见性

本课成员可以参与核验，作者不能自核。助教仍只能作核验参与者，不能以教师身份裁定/正式发分。与既有规则保持一致：同伴结论冲突转争议，教师裁定后不接受同伴改判；正式发分后整版核验冻结，下一版本重新复核。

**未发布提交不因核验而开放全文。**同伴只得到该条证据及其引用段落；没有正文 JSON、其他段落、教师批注或私有评分草稿。可读全文的作者、教师、助教或已获准发布版本读者才显示提交跳转按钮。正文中的图片只以引用段落的文字描述出现；未开放的媒体不绕过既有权限。

核验并不等于学业评分、来源真实性认证或著作权授权。失败证据不自动决定总分或封顶，仍由教师按量规判断；PENDING / DISPUTED 仍阻止正式发分。

## 并发与历史

新 `POST /evidence/{id}/decisions` 必须携带详情里的 `record_count` 作为 `expectedCount`。其他人先提交时返回409，页面保留判断依据，需明确刷新记录重新核对后才能再提交，不自动重试。已发分/权限变化等422/403同样需要刷新再确认。

核验和正式评价发布均先锁同一 submission 行，核验再锁 evidence 行，避免评分冻结与并发核验交错。该机制不是压力测试或分布式锁验证；已有账号被移出的并发边界仍见 [MEMBERS.md](MEMBERS.md)。

V7 为新核验保存 `verifier_role`，教师之后离开课程也不会把已裁定记录变回普通同伴判断。旧记录保留NULL，不从当前身份伪造历史；显示「身份未留存」。旧教师记录的阻断策略仅在其仍是当前教师时可识别；对于更早且身份已变化的记录无法追溯，需教师人工复核。旧 `POST /verifications` 仍兼容，不带冲突计数，但同样使用锁、身份快照和评分冻结规则。

新工作台每页最多20条，但工作台首页摘要仍沿用原课程证据列表接口，未改造为大规模聚合；不要把本轮描述为百万级证据检索。搜索只有数据库 LIKE，不含全文索引、OCR或语义向量检索。

## 输入保留与边界

详情中的判断依据在冲突、刷新和请求失败时保留在当前内存中。离开确认和beforeunload警告不能替代持久化；本轮没有核验判断草稿自动保存、localStorage备份或跨标签页恢复。刷新浏览器后未提交输入可能丢失，重要依据应先自行保存。与作品/评分草稿的自动备份能力不同。

教师评分草稿跳转前仍按已有flush流程保存；新工作台与评审跳转不会自动发布评分。所有来源、引用和操作者姓名作为普通文本呈现，外部链接仅允许http/https且noopener/noreferrer。

本期仅PC1280px及以上，兼容深浅色。AI修改建议由教师按作业开启，只在作者或教师主动生成时发送草稿正文（见[反馈右栏](FEEDBACK-SIDEBAR.md)）；核验工作台不调用AI，不自动核验、不发分、不向模型发送证据原文。MySQL、生产压测、灾备和安全审查尚未完成。

## 本地复验

在全新隔离演示库初始化完成后执行：

```bash
E2E_BASE_URL=http://127.0.0.1:8080 E2E_PASSWORD="$DEMO_PASSWORD" node scripts/evidence-e2e.mjs
```

会添加明确标注的功能验收任务、证据、成员关系、核验和评价，不可指向真实课程。该脚本拒绝非localhost域名。
