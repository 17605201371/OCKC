# 作业规则管理与历史保护

## 教师操作

课程作业卡片新增「管理作业」，仅当前任课教师可用，助教与学生不可操作。

- 修改标题、要求和截止时间。新的截止时间必须晚于服务器当前时间；没有实质变化不产生记录。
- 手动结束：立即停止新建作答和新提交，但保留既有草稿、保存能力、提交、评价、证据与社区记录。
- 重新开放：仅解除手动结束，且截止时间必须仍在未来。若已过期，先调整截止时间，再明确重新开放。
- 自然截止但未手动结束的任务，延期到未来会恢复作答与提交；页面会提示确认。手动结束的任务延期不会悄悄开放。
- 每次变更必填原因，写入教师操作记录，保留操作者、时间、递增版本和变更前后规则。列表展示最近 100 次；数据库不删除更早记录。
- `management_revision` 乐观锁避免另一教师/标签页的旧表单覆盖新规则。409 时输入保留，需明确重新载入。表单不是自动保存；关闭或刷新有未保存输入时提示。

AI 开关仍走既有独立策略接口，不随任务编辑覆盖；本次未接入 AI 模型。

## 学生体验与一致性

规则变更向本课程当前学生/助教生成通用站内提醒，不复制教师的变更原因。点击提醒定位任务卡片；提醒和记录与管理更新处于同一事务。教师不会收到自己操作的学生提醒。

已打开页面每 30 秒或重新获得焦点时刷新任务元数据；**不替换正在编辑的正文、标题或证据**。手动结束会显示提醒并禁用提交按钮。离线刷新失败时编辑页提示，不冒充已同步。所有最终资格仍由服务器检查；不是 WebSocket 即时推送。

开始作答与提交会锁定作业规则行，与教师修改串行校验；提交还保留原有作品锁、草稿 revision、幂等与评审约束。手动结束后重复已有成功幂等键仍返回原提交，不算迟交。教师结束作业不撤销已发布评价或社区版本。

本轮不支持删除任务、个别学生延期、迟交审批、定时发布或任务草稿。

## 提交时的任务规则快照

新提交保存 `assignment_snapshot_json`，包含任务 ID、标题、要求、截止时间、量规版本、管理修订号和手动状态。后续任务变更不改写快照，阅读/评审页可展开「提交时的任务规则」。作品自身内容哈希机制不变。

迁移前既有提交保持快照为空，页面明确标为未记录；**不使用当前规则回填并冒充历史规则**。任务变更历史可补充核对，但不声称能重建从未记录的过往规则。

## API 与迁移

- `PUT /api/assignments/{aid}`：title、requirements、dueAt（ISO Instant）、reason、revision。
- `POST /api/assignments/{aid}/state`：action（CLOSE / REOPEN）、reason、revision。
- `GET /api/assignments/{aid}/history`：仅本课教师，倒序最近 100 条；含 before/after。
- 作业列表新增 management_revision / manually_closed / updated_at；due_status 综合手动状态与截止时间。
- `GET /api/submissions/{sid}` 新增 assignmentSnapshot；旧提交可为 null。

三个管理 API 均检查当前任课教师，写请求检查 CSRF；409 为规则修订冲突，422 为不满足开放/日期条件。V5 新增作业管理字段、历史表与可空提交快照列，不重写既有正文与评分。

当前在 H2 MySQL 模式验收；MySQL 容器与生产迁移回滚演练尚未完成，部署前应备份并在预发布环境验证。
