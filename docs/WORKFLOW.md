# 教学工作流增量：消息、评分草稿与截止状态

## 消息中心

顶栏铃铛打开课程消息抽屉，支持全部/未读、标为已读、全部已读及游标分页。每 30 秒和窗口重新获得焦点时更新；不是 WebSocket 实时推送，也不发送邮件或短信。

提醒由真实业务事务创建：学生提交 → 本课教师；正式评价/教师批注 → 作者；学生回应 → 本课教师；核验更新 → 作者；证据争议 → 本课教师；课程内发布申请 → 本课教师；审核结果 → 作者。操作者不会收到自己触发的提醒。提交幂等重试不会重复生成通知，业务回滚不留下提醒。

消息只保存类型、路由目标、课程和通用标题，不复制私有评分草稿、总评或批注正文。按收件人和当前课程成员身份查询；教师专属提醒还检查当前教师身份。撤销成员权限后隐藏旧提醒，实际跳转仍由目标 API 检查权限。点击成功才标为已读；无权限、未保存输入或加载失败不会错误清除未读状态。

旧数据迁移后不倒灌历史通知，避免将历史操作冒充新消息。

## 教师评分草稿

私有草稿按「提交版本 + 教师」分开持久化。允许只填部分分数、尚未给出总评、不完整的 N/A 理由；但分数范围、编码和长度仍受校验。草稿不产生正式评价，不改变社区发布，不通知学生。

- 修改后约 1.2 秒自动保存；也可以「保存评分草稿」。批改队列仅标记**当前教师自己**的草稿，方便续评。
- 页面切换、课程切换、退出登录和发布评价前先保存。失败或冲突时阻止不安全离开；关闭浏览器时提示未保存状态。
- 自动保存失败时本机保留按用户与版本隔离的备份；重新进入后显式选择恢复或使用服务端草稿。共享电脑使用后仍应清除站点数据。
- 同教师多窗口使用 `revision` 乐观锁；旧窗口不得直接覆盖新草稿。
- 使用 `baseEvaluationRevision` 与正式评价绑定。正式评价被更新后，旧草稿标为过期，必须明确恢复并复核或放弃。正式发分仍检查完整 11 项、量规、证据状态与正式评价版本。
- 成功发分只清除发布教师自己的草稿；另一教师的草稿保留并标为过期。草稿删除不删除正式评价与历史。
- 学生、助教和其他课程教师不能读取或写入该教师的草稿；助教评分表单只读。

本机备份不是跨设备同步或正式历史审计的替代品；仅已保存到服务端的草稿可跨设备续评。当前不实现协同评分合并。

## 作业截止

作业列表和首页共享进行中、24 小时内截止、已截止状态；编辑页显示截止提醒，列表支持即将截止/已截止筛选。时间以列表返回的 `server_now` 校准，不直接相信客户端时钟；页面每 30 秒更新显示，最终以服务器提交校验为准。

已截止且未开始：禁止新建作答。已有草稿：允许继续整理保存和查看历史，但禁止提交新版本。幂等重复请求可取回此前成功的提交，不算迟交。已支持教师整份作业延期及手动结束/开放；仍不提供个别学生延期或迟交审批。详见 [作业管理](ASSIGNMENT-MANAGEMENT.md)。

## 单篇帖子的终审

作业级「结束作业」是整班一起停；每篇帖子什么时候算完成，由教师逐篇裁定。此前没有终态，学生可以一直「提交 → 评分 → 再提交」，双方都不知道停在哪里。

- `entry.state` 三态：`OPEN` 进行中、`REVISION` 已打回、`PASSED` 已通过定稿。
- 教师批改页底部「终审」：「通过定稿」要求该版本已发布正式评价；「打回修订」必须写原因，学生端直接显示这段原因。
- `PASSED` 后提交接口返回 422，学生仍可保存草稿和查看历史；误点可在同一位置「撤销定稿」。
- 截止或结束作业不自动定稿：教师仍可批改和终审，未定稿的保持最后状态。
- 通知类型 `ENTRY_VERDICT`，路由到最新提交版本；学生首页与作业列表显示「已通过定稿 / 已打回 · 待修订」。
- 接口：`POST /api/entries/{eid}/verdict`，body `{action: PASS|RETURN|REOPEN, reason}`，仅任课教师；`PASS` 未评分返回 422，`RETURN` 无原因返回 422。

### 交新版本的前置条件

上一版必须有教师反馈，才允许交新版，避免老师还没看学生就反复刷版本。以下任一条件成立即放行：

1. 上一版有生效中的正式评价（`evaluation.active = TRUE`）；
2. 上一版有教师段落批注（`feedback` 有记录）；
3. 条目处于 `REVISION`（教师已打回，明确要求修订）。

三者都没有时返回 422「上一版本还没有教师反馈，请等待老师评阅或批注后再修订」。第 3 条不可省略：被打回的那一版往往尚未评分，若只认评价，「打回 → 修订 → 再提交」会死锁。

## 列表只看最新版本

同一篇作品改过几版，库里就有几份 submission。此前批改中心、教学进展、证据核验三处都按 submission 平铺，同一篇会以 v1 / v2 两行出现——旧版本已经不能评分，点开只会重复看同一份作业。三处现在统一只列每篇作品的最新版本：

- **批改中心**：`review-workbench` 默认 `versions=LATEST`（`NOT EXISTS ... nv.version_no > v.version_no`），统计口径与列表一致，16 篇作品就是 16 行。要看旧版本在「高级筛选 · 版本范围」里切到「全部提交版本」，切换后顶部会说明当前范围。
- **教学进展**：`dashboard` 固定按最新版本取数，否则「待评审 / 已评价」会被旧版本重复计入。
- **证据核验**：`evidence-workbench` 的列表与四个状态计数都加了同一条条件。旧版本上的证据已被新版本取代，核验它没有意义；需要回看时进该版本的阅读页，证据仍在。

版本本身没有删除，学生端的「版本记录」与阅读页的「修订历史」仍列全部版本——那是作者和教师需要的历史，不属于待办列表。

## 社区阅读时谁能看到批注

批注是对「某一版」说的过程性意见，不是成品的一部分。此前阅读页不分角色，任何能打开这篇的人都会看到全部未解决批注的正文高亮，带来三个问题：读者把「老师还没点已解决」误读成「这篇有很多毛病」；批注措辞是私下对作者说的；作者再改一版后锚点变 stale，高亮和正文对不上。

可见性按角色分三层：

| 角色 | 正文高亮 | 右栏 | 修订历史 |
| --- | --- | --- | --- |
| 作者本人 | 全部未解决批注 | 教师反馈 + 总评 | 全部版本 |
| 教师 / 助教 | 全部 | 批改面板 + 终审 | 全部版本 |
| 同学 / 访客 | 无 | 质量分 + 总评，未公开时写「该知识贴未展示反馈信息」 | 只列已发布版本 |

- 阅读页的右栏默认收起（编辑页、批改页仍默认展开）：知识社区是只读的成品面，多数时候没有要看的东西，需要时点「质量与版本」或右缘的「反馈」再展开。

- 裁剪在服务端 `getSubmission` 完成：无权限时 `feedback` / `priorFeedback` 返回空数组，并带 `feedbackVisible=false`，前端只是不渲染，拿不到数据。
- 修订历史把批注挂回它针对的那一版（`GET /api/entries/{eid}/versions`），读者只看得到 `PUBLISHED` 的版本，草稿版本属于作者和教师。
- 作者申请发布时可以勾「公开教师批注作为范例」（`publication.share_feedback`，默认 `FALSE`）。勾选后该版批注对读者可见，但学生对批注的回应（`feedback_action`）始终不公开——公开的是「老师说了什么」，不是师生往来。
- 复评会撤回发布（`publicationAfterEvaluation`），撤回后 `share_feedback` 保留，重新发布时沿用作者上次的选择。

## 数据与 API

Flyway V4 新增 notification、review_draft 及索引，不改写既有提交与正式评价。

- `GET /api/notifications?unread=false&before={id}`：每页最多 20，返回 items/unreadCount/hasMore/nextCursor。
- `PUT /api/notifications/{id}/read` / `PUT /api/notifications/read-all`：只更新当前用户有权限看到的消息，需 CSRF。
- `GET /api/submissions/{sid}/review-draft`：返回当前正式评价修订号和当前教师的私有草稿。
- `PUT /api/submissions/{sid}/review-draft`：items、summary、gateReason、revision、baseEvaluationRevision；冲突为 409。
- `DELETE /api/submissions/{sid}/review-draft`：JSON revision，保护并发删除。
- 作业列表新增 server_now / due_status；批改队列新增本人 review_draft_updated_at，不返回评分草稿正文。

AI 反馈已接入模型服务（`step-3.7-flash`，OpenAI 兼容 `/chat/completions`），入口仍由教师按作业开关，生成结果只作修订建议，不进入正式评分。

- 该模型关不掉推理，`max_tokens` 给到 16000 才能跑完「推理 + JSON」；额度不足时 `finish_reason=length`、正文为空，接口返回 FAILED。
- 建议按 entry 存、不按 revision 过滤：采纳会改正文、revision 随之变化，按 revision 查会让其余建议消失。
- 「采纳并替换」用 `quote` 在段落纯文本里定位、用 `replacement` 覆盖该范围；`replacement` 里的 `$...$` 与「被替换范围内出现过的公式」都还原成 inlineMath 节点；quote 边界切在公式中间时放弃自动替换，提示手动改。
- 撤销快照只在当前页面有效，刷新后按钮退回「已替换」；替换与撤销都会触发草稿自动保存。

## 作业类型与证据核验策略

发布作业时选择类型，决定学生端与批改端的形态：

- **知识帖（POST）**：按段落自由写作，沿用四维量规评分。
- **步骤（STEP）**：作答区按步骤卡呈现，每步先命名（这一步要解决什么），再写这一步的推导；「添加一步」在末尾追加一步。底层仍是同一份 ProseMirror 文档（步骤名就是该步的标题），因此版本对比、批注锚点与导出逻辑不变。批改侧栏「步骤分」列出各步与得分，点任一步会滚到正文对应卡片并短暂高亮；点中某步后在下方「老师点评」卡里填问题类型标签（忽略题设条件 / 计算或单位错误 / 概念混淆 / 论证跳跃 / 表述不清，每步最多 4 个）与一句评语。点评与步骤分随评分草稿保存，发布后学生端把评语显示在该步正文下方。

步骤分就是步骤型作业的正式成绩：`q_final` 按「各步得分之和 ÷ 满分之和 × 100」换算成百分制，`details/dimensions` 存空数组，因此步骤作业不再显示四维评分面板（教师端、学生端都不显示）。知识帖作业仍走 11 项四维加权，两条路径互不影响。切步只认标题层级——若整篇没有二级标题，退化为使用现有全部标题；没有任何标题时不出步骤面板，也不阻断发分。

证据核验策略按作业配置，用来控制教师负担：

- `REQUIRED`：每条证据都要有结论才能发分（旧行为）。
- `DISPUTED`（默认）：待核验证据不阻断发分，只有同伴结论冲突产生的争议必须先裁定。
- `OFF`：核验记录仍保留，但不参与发分判断。

迁移 `V18` 把历史作业一并落到 `DISPUTED`，原因是此前「任一条待核验即不能发分」等于要求教师核完全班每条证据。需要严格模式的作业可单独改回 `REQUIRED`。
