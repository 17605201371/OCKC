# 指定版本发布审核与记录

本轮范围：PC 开发版，课程内展示，不是校外公开或生产上线验收。

## 使用入口

- 知识社区保留已发布条目、标题/作者搜索和最近发布/质量排序。
- 教师在“等待你的发布审核”查看指定提交，点击“同意发布”或“退回”，填写处理理由后确认。
- 社区及冻结版本阅读页提供“发布审核与记录”（教师）或“我的发布记录”（作者）。可按标题、作者、作业搜索和状态筛选，每页展示 20 条。
- 作者在已评分冻结版本中申请发布；申请说明选填。已退回/已撤回的同一提交允许重新申请，也可先修订并提交新版本，再申请新版本。
- 退回理由、申请说明、处理人及历史只向当前本课作者、任课教师开放。其他学生/助教不能读取私有审核详情；助教仍保留既有提交只读评审权限。

## 状态与不可变边界

`未申请 / WITHDRAWN / RETURNED → PENDING → PUBLISHED / RETURNED / WITHDRAWN`

- 申请前必须有有效教师正式评价；作者必须仍是课程成员。
- `APPROVE` / `RETURN` 只允许教师处理待审核申请；退回不是删除，也不改写正文或评分。
- 作者/教师可撤回待审核申请或已发布展示；重复处理和不相容状态返回 409。
- 正式复评时，待审核或已发布记录自动变为 `WITHDRAWN`，追加 `REGRADE` 事件；再次展示需基于最新评价重新申请。此前已退回/已撤回的记录不追加重复撤回事件。
- 展示固定 `submission_id`，后续草稿标题、正文、插图不会替换已发布版本。
- 撤回后同伴不能继续从接口读取完整提交或仅由该发布版本授权的图片。已被用户下载的内容无法从其设备收回。
- 最近发布按本次发布时间排序，旧记录无该字段时回退至审核/申请时间，不再简单按 publication 主键排序。

## 历史与并发

Flyway V8 增加 publication 的 `revision`、申请所依据的 `requested_evaluation_revision`、最近理由及发布时间，并新增 `publication_event`。

每次操作追加：前后状态、动作、理由、操作者、当时角色、评价修订号与时间。旧发布记录保留原状态/时间，缺失的旧过程、申请评价号不补造。

写操作与复评统一先锁 submission，再处理 publication；新接口提交客户端 revision，409 不追加事件、不覆写新状态。界面保留理由，必须显式刷新并核对后再提交；刷新后不再适用的操作保持禁用。模态框使用原生 dialog、键盘 Escape 和焦点返回，带未提交理由时关闭需确认。

旧 `/publication` 与 `/actions` 接口为演示脚本兼容保留，仍执行权限、状态和行锁校验并记录默认操作说明，但不要求客户端 revision。新版界面全部使用带 revision 的请求接口；旧客户端不具备同等旧窗口冲突提示能力。

## 验证与边界

- 新增 `PublicationWorkflowTest` 20 项：角色/跨课程/CSRF、退回重申、状态冲突、历史隐私、复评撤回、草稿与公开版本隔离、旧记录兼容。
- `scripts/publication-e2e.mjs`：10 项浏览器检查、9 个截图，覆盖真实退回、重申、撤回、旧窗口理由保留、复评撤回、搜索排序、深色与 1280px。
- 修复教师批改列表刷新中可点击但动作被忽略的问题：加载期间行按钮禁用并标注 aria-busy。
- 本期发布记录/历史接口仍是按当前课程及本人权限读取全量、前端筛选分页；**尚非大规模服务端分页方案**。海量课程/长历史、真实并发压力、MySQL 实机迁移、安全审计、备份恢复演练仍待专项验收。
- AI 仍未接入；教师开关只控制反馈入口，不生成审核结论、评分或虚构建议。

复验必须新建隔离 H2 演示数据库；脚本会修改验收课程，不得指向真实教学数据。
